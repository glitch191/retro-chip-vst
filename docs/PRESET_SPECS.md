# Preset library specification

Targets: NES 250-350, SNES 250-350, Genesis 300-400 presets after perceptual
de-duplication (800-1100 in total). Presets are generated by `tools/gen_presets.py`
from curated seed patches and documented variation rules; nothing is added one by one.

## Files

```
tools/gen_presets.py            entry point: python tools/gen_presets.py [--jobs N] [--chip nes|snes|genesis] [--qa]
tools/presetgen/__init__.py
tools/presetgen/model.py        Preset dataclass, parameter bounds loaded from tools/presetgen/params/<chip>.json
tools/presetgen/naming.py       mechanical naming from parameters
tools/presetgen/qa.py           perceptual de-duplication + report -> docs/PRESET_QA.md
tools/presetgen/seeds/nes.py    curated seed patches + variation rules per category
tools/presetgen/seeds/snes.py
tools/presetgen/seeds/genesis.py
tools/presetgen/params/<chip>.json  parameter table exported from the engines (key, min, max, default, isInteger, labels)
assets/presets/<chip>.json      generated bank (JSON array), committed
docs/PRESET_QA.md               generated QA report, committed
```

The parameter tables in `tools/presetgen/params/` are exported by the C++ tool
`chiptool dump-params` (built from `dsp/tools/chiptool.cpp`) so that Python never
guesses hardware bounds. Until the engines exist they are hand-written from
`docs/ENGINE_SPECS.md` and must match it.

## Preset document

See `docs/PLUGIN_SPECS.md` ("Presets"). Keys are engine parameter keys without the chip
prefix. `global` may set arpeggiator/glide parameters (used by "Arp" categories).

## Categories and subcategories

NES: Lead (Pulse, Vibrato, Sweep, Octave), Bass (Triangle, TriangleGated, Pulse),
Drums (Kick, Snare, HiHat, DMC), Arp (Triad, Interval), SFX (SweepUp, SweepDown,
Noise, Zap).

SNES: Instrument (Piano, Strings, Brass, Guitar, Woodwind, Organ), Bass (Sample,
Short), Pad (Echo, Strings, Choir), Drums (Kit, Velocity), SFX (Noise, PMON).

Genesis: FM Bass (Alg, Feedback, Detune), FM Keys (EPiano, Bell), FM Brass (Stab, Brass,
SSG), FM Pad (Slow, Unison, LFO), DAC (Drums), PSG Lead (Solo, Doubled), PSG Bass,
PSG Drums (Periodic, White). FM leads and guitars are in FM Brass / Brass, wind leads in
FM Pad / LFO, organs and strings in FM Pad (`docs/research/genesis-sound-design.md`,
"Category mapping").

## Seeds and variation rules

Each category has 10-20 seed patches, written by hand in the seeds module with every
parameter set explicitly and a comment on the intended sound. Each seed declares its
variation axes as lists of parameter values, for example:

```python
Seed(name="Square Lead", category="Lead", subcategory="Pulse",
     params={...}, axes={"p1_duty": [0, 1, 2, 3], "transpose": [-12, 0, 12],
                         "vibrato": [("off", {...}), ("slow", {...}), ("fast", {...})]})
```

`gen_presets.py` expands the Cartesian product of axes for every seed, then runs QA.
Axis values must be hardware-valid; the generator asserts every value against the
parameter table and fails loudly otherwise.

## Perceptual QA (`qa.py`)

Two presets are duplicates when every parameter distance is below its threshold:

* integer register parameters: identical;
* volume/level (NES volume, TL, attenuation, VOL): within 1 step is a duplicate only if
  no other parameter differs (a 1-step volume change alone is not a new preset);
* time parameters (frames, ms, rates): a relative difference under 15 % is a duplicate;
* duty, algorithm, waveform-defining parameters: any change is significant;
* AMS/FMS/LFO: depth index change of 1 at the low end (0 -> 1) is significant; changes
  between the two highest depths are duplicates.

When the engine renderer is available (`chiptool render`), QA additionally renders 1 s of
a C4 note per preset and computes a log-spectral distance (mel bands, 40 bands) and an
envelope distance; pairs under the documented thresholds are removed too. The report
lists every removal with the pair and the reason. Batch processing uses a process pool
sized to `os.cpu_count() - 1` (override with `--jobs`), and results are sorted by
deterministic keys before writing.

## Naming

`<Chip> <Category> <Descriptor...>` built from the seed's base name and the axis values
in a fixed order, e.g. `NES Lead Duty25 Vibrato Slow`, `SNES Pad Strings LongRelease
Echo3`, `Genesis Lead FM Alg4 LFO Vibrato2`. Names are unique within a bank; the generator
appends a register/index suffix if a collision remains after descriptors.
